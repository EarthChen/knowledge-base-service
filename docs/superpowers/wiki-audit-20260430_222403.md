## 1. Executive Summary

KB Service 在**工程化能力**上显著领先竞品（增量更新、多视图、Agent MCP、记忆演化、导出生态均为独有或领先能力）。上轮迭代新增的 DomainComplexityScorer、多模态图表生成、WikiQualityBench 有效缩小了内容生成智能度差距。

但审计发现 **4 个 P0 正确性问题**、**6 个 P1 体验/可维护性问题**、**9 个 P2 优化项**，需要按优先级处理。

## 2. P0 — 关键正确性问题 (4 个)

### P0-1: quality_gate 中英语言不匹配

- **现象**: `WikiQualityEvaluator.structural_check` 检查英文 heading (`## Overview`, `## Key components`)，但 `TopicPageComposer` 生成中文 (`## 业务概述`, `## 核心流程`)
- **后果**: 质量评分系统性偏低，触发不必要的 heal 循环浪费 LLM token
- **位置**: `wiki/quality_evaluator.py` structural_check vs `wiki/topic_page_composer.py` prompt
- **修复建议**: structural_check 同时识别中英文 heading，或根据 WikiConfig.language 动态选择

### P0-2: 前端域树"批准"不持久化

- **现象**: `WikiToolPanel` 中 `onApprove={() => setDomainReviewOpen(false)}` 只关闭 UI，不调用任何 API
- **后果**: 用户点击"批准"后以为审核完成，但刷新页面后再次显示 pending
- **位置**: `dashboard/src/components/wiki/WikiToolPanel.tsx:167-175`
- **修复建议**: 调用 `useSetPageReview` 或新建 domain-level review API

### P0-3: 每域重新生成是空函数

- **现象**: `onRegenerate={() => { /* Per-domain regenerate API not wired yet */ }}`
- **后果**: 用户看到重新生成按钮但点击无任何效果
- **位置**: `WikiToolPanel.tsx` 同上
- **修复建议**: 接入 `businessWikiGenerate` 的 per-domain 参数，或暂时隐藏该按钮

### P0-4: TOPIC 页无法生成语义图表

- **现象**: `SemanticDiagramGenerator._should_generate` 对 `PageType.TOPIC` 返回 `False`
- **后果**: LangGraph compose 中 topic 页面图表调用全部空操作
- **位置**: `wiki/semantic_diagram_gen.py` `_should_generate` 方法
- **修复建议**: 将 TOPIC 页视为可生成图表的类型，根据内容关键词决定生成哪些图表类型

## 3. P1 — 重要问题 (6 个)

### P1-1: LangGraph 管道未接入生产路径

- **现象**: MCP 和 HTTP 生成全走 `WikiService`，`WikiPipelineAdapter.generate_wiki` 委托给 `WikiService.generate`
- **风险**: 双管道并行维护，测试与生产漂移
- **状态**: 上轮已制定迁移提案，待执行

### P1-2: WikiTopicContent 缺少 businessId 传递

- **现象**: `WikiTopicContent` 调用 `MarkdownRenderer` 时未传 `businessId` / `wikiLinkParams`
- **后果**: 主题页内 `[[wikilink]]` 无法正确解析和预览
- **位置**: `dashboard/src/components/wiki/WikiTopicContent.tsx`

### P1-3: Review mutations 无用户可见错误状态

- **现象**: `useSetPageReview` / `useRegeneratePage` 失败时只 `console.error`
- **后果**: 用户不知操作是否成功
- **对比**: `WikiContent` 中注释功能用了 `toast` 提示

### P1-4: Cache invalidation 逻辑缺陷

- **现象**: `invalidateWikiQueriesForBusiness` 匹配 `queryKey[2] === businessId`
- **但**: `useWikiNavigation` 的 key 是 `["wiki", "navigation", repository, path]`，`k[2]` 是 repo 不是 business
- **后果**: wiki 生成完成后导航缓存可能过时

### P1-5: service.py 体积 (3249 行) + 大量宽泛异常

- 多个 `except Exception` 块，虽多数有日志但风险是掩盖真实缺陷
- 迁移提案中已规划拆分为 4 个模块

### P1-6: DEPLOYMENT.md 与 config.py 默认值不一致

- 文档说 `WIKI__DEEP_RESEARCH_ENABLED=false`、`WIKI__MCP_SERVER_ENABLED=false`
- 代码默认值都是 `True`
- 误导部署配置
